# Strict VLM router integration audit

Date: 2026-11-11. Implementation and tests are confined to the component-contributions worktree. The teammate's unpublished checkpoint/code was not available to this integration, and no model weights were downloaded or trained. The test evidence below is transport-contract evidence, not real-VLM accuracy or superiority.

## Implemented contract

`VLMRouter` implements the existing `RouterBackend.submit(RouterRequest) -> RouterResponse` contract. The caller provides a RouterConfig and therefore the model and base endpoint; optional explicit constructor overrides are supported. Factory construction retains the existing live-call opt-in. Local vLLM servers need not require authentication; when configured, credentials come from caller input or the existing credential environment-variable names.

The request must carry a detached `CameraObservation`: encoded PNG/JPEG bytes, capture simulation timestamp, ego lane and speed, and dimensions. Empty, mismatched-signature, oversized, future-dated or stale images fail before transport. The default maximum submission image age is 0.5 seconds and is configurable by constructor. MIME/signature checks are lightweight; full codec decoding remains the server's responsibility. The router declares `requires_camera=True`, so the controller captures on the simulation thread before submitting a background request. Camera bytes are immutable and no Panda3D object is sent to a worker.

Payload contents are one image data URI plus ego lane and speed text, and a fixed maneuver-description system prompt. The current skill, trigger reason, critic score and surrounding-object simulator state are not included. A contract test changes privileged state while holding the image constant and confirms the payload hash remains unchanged. This prevents the current-skill-copy shortcut reported by the teammate; it does not solve visual blind spots or establish generalization.

The request sets `temperature=0`, `max_tokens=1`, `stream=false`, and `structured_outputs={"choice":["A","B","C"]}`. A/B/C map to CRUISE_RIGHT/OVERTAKE_LEFT/RETURN_RIGHT. The response parser requires exactly one choice and one permitted letter after trimming surrounding whitespace. Explanations, skill names, multiple letters, refusals, tools and invalid finish reasons fail. `finish_reason=length` is accepted only for an already complete valid letter: with a one-token cap, the endpoint may reach its token limit before emitting a separate EOS token. If the server reports completion token usage, a value other than one fails. No tokenizer IDs are guessed; actual single-token compatibility must be checked with the deployed model/server.

No failure path invokes scripted routing, even if generic config defaults allow fallback. HTTP 408/429/5xx and transient transport errors may retry; authentication/other 4xx and malformed completions do not. Retry count is finite, backoff must fit within the remaining budget, each transport timeout is the remaining shared budget, and late responses are rejected. The budget is min(configured timeout, request deadline when present). This is not a hard real-time thread-cancellation guarantee: stdlib socket timeouts do not guarantee interruption of uncooperative custom transports or every DNS/network edge case. The controller must continue enforcing its independent pending-call deadline.

Responses use measured elapsed wall time for `latency_s`, `wall_latency_s` and `ready_at=request.t+elapsed`. Metadata includes prompt SHA-256, encoded-image SHA-256, capture timestamp, image age at submission, retry attempt count, returned model, finish reason and normalized token usage. Prompt/image hashes support repeated-image audits; they do not imply uncached encoder computation. The backend does not change pixels to manufacture cache misses. Injected transports default to `live=False`; an actual custom live transport requires explicit `transport_is_live=True`. Real-model evaluation still needs endpoint and checkpoint provenance.

## Primary documentation checked

- [vLLM structured outputs](https://docs.vllm.ai/en/stable/features/structured_outputs/) documents `structured_outputs.choice`. Its migration notes say the older `guided_choice` field was removed in v0.12.0. Direct HTTP JSON uses the structured_outputs field at the payload top level; SDK examples place it inside `extra_body` to forward it.
- [vLLM multimodal inputs](https://docs.vllm.ai/en/stable/features/multimodal_inputs/) documents image content blocks and base64 data URIs.
- [vLLM OpenAI-compatible server](https://docs.vllm.ai/en/stable/serving/online_serving/openai_compatible_server/) describes Chat Completions compatibility and multimodal parameters. This integration targets a server that supports the current vLLM structured-output extension; it does not silently retry without constraints on an incompatible server.

## Validation

Offline tests cover payload information isolation, all A/B/C mappings, stop/length handling, token/image/timing metadata, missing/invalid/stale images, bounded retry budgets, over-budget rejection, permanent failures, circuit opening/reset, optional authentication, malformed responses, factory opt-in and the camera-required flag. The existing router-core tests run alongside these. Ruff and targeted mypy check the new implementation.

Physical camera appearance, true model response quality, tokenizer compatibility, target-server latency, and closed-loop driving behavior require separate endpoint/camera experiments. The root task owns that wiring and any physical smoke test; neither the teammate's reported frame accuracy nor the mocked responses are promoted to a verified result here.

### Exact compatibility differences

- Original v1 system prompt explicitly assumes every other vehicle is parked at speed zero and gives detailed lane-occupancy rules. The new strict adapter has a shorter system prompt and no parked-vehicle assumption.
- Original state text includes ego lane, **current skill**, and a literal **20 m/s** speed. Training frames actually set ego velocity to zero before rendering. The new adapter removes the current-skill cue and reports observed ego speed to three decimals. These are material prompt/distribution changes; neither v1 accuracy nor v1 latency transfers automatically.
- Original generation uses MetaDrive 0.4.3 default RGB image observations, 640×360, `norm_pixel=False`, one frame, two simulation steps after placing vehicles, and BGR-to-RGB channel reversal before PNG storage. The local adapter also uses 640×360 and channel reversal, but explicitly positions its camera; camera pose, scene geometry, asset and EGL/software-render differences must be checked visually rather than assumed equivalent. The training generator uses lane centers 0 and 3.5 m; the local regulator scenarios use 0 and 4 m.
- Original processor bounds are min_pixels=784 and max_pixels=1,254,400. vLLM 0.33.0 evaluation uses bf16, max_model_len=4096, one image per prompt, prefix caching, GPU memory utilization 0.85, seed zero, temperature zero and one generated token. The strict HTTP adapter does not set processor bounds; a matching server must configure them.
- Original decoding restricts allowed token IDs obtained from the deployed tokenizer for A/B/C. The strict adapter uses `structured_outputs.choice` and validates one-letter output. Both constrain the choice set, but they are not proven identical decoding paths; a faithful reproduction should verify each letter encodes to one token and use the original allowed-token-ID restriction in a separate compatibility client.
- Original evaluation changes one random pixel per call to avoid vision-image-cache hits, performs three warmup calls per dataset and times in-process `llm.chat`, excluding image preparation. The local adapter preserves pixels and measures client payload/inference/retry parsing, with main-thread camera capture separately accounted by the controller. These timing numbers are not directly comparable.
